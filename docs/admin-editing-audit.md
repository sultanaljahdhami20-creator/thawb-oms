# مراجعة خيارات التعديل للأدمن

تغطي هذه المراجعة خيارات تصحيح البيانات المضافة للأدمن.

| المكان | التعديل المتاح |
|---|---|
| أخطاء الجاكيتات ← تفاصيل الطلب ← بلاغ الجاكيت | أُضيف تعديل عدد الجاكيتات المتأثرة، صاحب الجاكيت، النوع، المقاس، الوصف، رابط الصورة، حالة البلاغ، والطلب المرتبط |
| أخطاء الجاكيتات ← الملاحظات | أُضيف تعديل ملاحظات الطلب وملاحظات بلاغ الجاكيت المحفوظة سابقًا |
| المصاريف | أُضيف تعديل التاريخ، الفئة، المبلغ، والملاحظة |
| الحسابات ← المدفوعات | أُضيف تعديل المورد، التاريخ، المبلغ بالدرهم، طريقة الدفع، المرجع، والملاحظة |
| الطلب ← سجل المدفوعات | المبلغ والتاريخ كانا قابلين للتعديل؛ أُضيف المرجع والملاحظة |
| الطلب ← تعديل | أُضيف تاريخ الطلب وإمكانية تفريغ اسم العميل الاختياري؛ بقية حقول الطلب موجودة سابقًا |
| التعويضات ← مراجعة | أُضيف تعديل الطلب المرتبط، السبب، التفاصيل، الحالة، سبب الرفض، والتعليقات؛ العدد والقيمة والنسبة ومعلومات الدفع ورسالة العميل قابلة للتعديل سابقًا |
| الحسابات ← التقارير المحفوظة | أُضيف تصحيح الرصيد المتاح، مع إعادة حساب صافي المركز بناءً على فرق الرصيد |
| الموردون ← تعديل الطلبات | أُصلح الحفظ في قاعدة البيانات؛ كان التعديل يقتصر على الحالة داخل الصفحة |
| الموردون، المستخدمون، الإعدادات، أسعار الأنواع، سعر الصرف، سعر التوصيل | خيارات التعديل موجودة سابقًا |
| رقم الطلب، حالة الطلب، الاستعجال، دفع التوصيل | لها خيارات مستقلة موجودة سابقًا |

## ما لا يزال بدون تعديل مباشر

- سجلات النشاط والتعديلات والحالات السابقة، وأسماء منفذي العمليات وتوقيتها التلقائي: تبقى كسجل تاريخي. يمكن تصحيح البيانات الحالية مع تسجيل تصحيح جديد.
- المجاميع والرصيد المتبقي والأرباح والتكلفة ومبلغ التعويض المحسوب: تتغير من بياناتها الأصلية، ولا تُكتب يدويًا.
- لقطة التقرير المالي المحفوظة ولقطة قيمة الطلب وعدده عند طلب التعويض: ليست حقول إدخال يدوي. لتقرير يعكس البيانات الحالية يُنشأ تقرير جديد؛ الرصيد المدخل يدويًا أصبح قابلًا للتصحيح. تغيير الطلب المرتبط بالتعويض يحدث لقطة الطلب.
- المعرّفات الداخلية للسجلات تُنشأ تلقائيًا. رقم الطلب التجاري له خيار تعديل مستقل.
- الملفات المطبوعة أو المصدّرة سابقًا: يجب إعادة إصدارها بعد تصحيح السجلات.

## التحقق والحدود

- خيارات التصحيح الجديدة ظاهرة للأدمن فقط؛ الصلاحيات السابقة للموظفين تبقى كما هي.
- التحقق من عدد صحيح للجاكيتات ضمن عدد الطلب، ومن الحقول المطلوبة والمبالغ.
- تصحيح بلاغ الجاكيت يزامن العدد القديم المحفوظ داخل الملاحظات، ويحتفظ بالملاحظات وسجل الحالة.
- الحفظ الجديد لا يعلن النجاح إذا رفضت قاعدة البيانات التغيير أو لم يرجع سجل محفوظ.
- اختبارات البيانات تستخدم قاعدة بيانات وهمية؛ لم نغيّر بيانات التشغيل أو سياسات صلاحيات قاعدة البيانات. حراسة دور الأدمن هنا ضمن التطبيق، وفق نظام تسجيل الدخول الموجود.

### نتائج الاختبارات

- نجح بناء التطبيق و29 اختبارًا آليًا.
- نجح اختبار متصفح ببيانات وهمية لتعديل بلاغ الجاكيت ثم إعادة تحميله، فشل حفظ المصروف وإعادة المحاولة، دفعة المورد، إعادة حساب التقرير، التعويض والتعليقات والملاحظات.
- نجح اختبار نموذج التعديل بالعربية على عرض جوال، واختبار إخفاء خيارات التصحيح الجديدة عن حساب الموظف.
- الملفات الجديدة وصفحة التعويضات اجتازت فحص الجودة. الفحص العام يحتوي على 65 ملاحظة سابقة في App.jsx؛ العدد نفسه في النسخة الأصلية.
